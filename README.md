# 展柜照度剂量复核

文保员用的小型网页工具：上传两张 CSV（展品摆放时段、各柜整小时剂量），
系统按照度上限推算每件展品可能受到的剂量区间，并给出“确定超限 / 确定未超 / 待核”的结论。

## 启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

数据库落在 Docker 具名卷 `exhibit-data`（容器内 `/data/exhibits.sqlite3`），
重建容器不会丢数据。首次上传前页面会自动建表。

本地开发（不建镜像）：

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:create_app --factory --reload
```

测试：`pip install pytest httpx && pytest`

## CSV 格式

摆放表 `placements.csv`（UTC，精确到整分钟，起点含、终点不含）：

```csv
exhibit_id,cabinet_id,start,end
MS-001,CAB-A,2026-05-01T09:00Z,2026-05-01T11:30Z
MS-002,CAB-A,2026-05-01T09:15Z,2026-05-01T09:45Z
```

剂量表 `doses.csv`（每柜每个 UTC 整小时一行，单位勒克斯·分钟）：

```csv
cabinet_id,hour,dose_luxmin
CAB-A,2026-05-01T09:00Z,420
```

页面右上角可直接下载这两份示例，仓库里也有一份在 `sample_data/`。

## 规则与算法

**首次上传**必须同时给出两张表、统一的照度上限（勒克斯）和每件展品的剂量阈值
（勒克斯·分钟）。两项参数一经确定不可再改，后续换报只需上传要换的那张表。

**整表退回**：剂量为负、或某个小时剂量超过 `照度上限 × 60`、时间不是 UTC 整分钟、
摆放区间 `end <= start`、同一展品时段重叠、同柜同小时重复行、表头不符等，
任一出现即整份拒绝，原数据和名单保持不变。

**剂量上下界**：某柜某小时测得总量 `D`，照度始终在 `[0, cap]` 内。展品在该小时
停留 `m` 分钟，则其受到的剂量满足

- 上界 `min(D, cap × m)`；
- 下界 `max(0, D − cap × (60 − m))`。

同一展品在同一小时内多次进出**同一柜**，分钟数相加后共用该柜该小时总量；
不同柜的小时总量互不相干，分别计算再求和。缺测的柜·小时没有 `D`，
只受照度范围约束，即 `[0, cap × m]`。

**结论**：下界 > 阈值 → 确定超限；上界 ≤ 阈值 → 确定未超；否则 → 待核。

**换报**：每次提交是一笔 SQLite 事务。摆放表整份替换后，只有摆放行真正变化的展品
会重算；剂量表整份替换后，只有“实际变化了的柜·小时”所覆盖的展品会重算。
换报后不再有任何摆放记录的展品会从名单中撤下。事务失败则数据与名单原样保留。
并发换报按到达服务的顺序生效（进程内票据闸门 + `BEGIN IMMEDIATE`）。

## 结构

```
app/
  main.py      FastAPI 路由与页面
  service.py   换报事务、受影响展品判定、名单维护
  assess.py    分小时切分、上下界与结论
  csvio.py     CSV 解析与整表校验
  db.py        SQLite 表结构与事务封装
  templates/   名单、详情页
tests/         算法、校验、并发与网页端测试
```

## 已知边界

- 只支持单进程运行（`--workers 1`）。多副本部署时进程内票据闸门失效，
  需要换成数据库序列或外部队列来保证跨进程顺序。
- 剂量界限假设同一小时内的照度可任意分布，只受 `[0, cap]` 约束；若同一柜同小时
  有多件展品，各自的区间是独立成立的，并非一份可行的联合分配。
- 尚未做登录鉴权与上传大小限制，仅适合放在内网使用。
